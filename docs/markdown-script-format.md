# Markdown 口播稿格式说明

本文说明如何把口播稿整理为可直接上传的 Markdown 文件，适用于人工整理口播稿，也适用于让 AI 将普通文章二次整理成上传文件。

## 1. 文件基本要求

- 文件扩展名必须是 `.md`。
- 文件编码必须是 UTF-8；带 UTF-8 BOM 的文件也可以被解析。
- 文件中必须且只能有一个非空的一级标题（H1），格式为 `# 标题`。
- 一级标题后必须且只能有一个四列表格。
- 表格至少必须包含一行口播数据，不能只有表头和分隔行。
- 标题和表格之外不能有正文、二级标题、列表、备注或其他内容。
- 表格的每一行都必须使用首尾竖线 `|` 包围。
- 单元格正文中如果需要使用字面竖线 `|`，必须写成 `\|`，否则解析器会把它当作新一列。例如，上传文件中的 `选择 A \| B` 会被解析为“选择 A | B”。
- 固定表头的列名和顺序不能修改。为统一格式，请原样使用下面的表头和分隔行。解析器对分隔行的核心要求是恰好包含四个有效分隔单元格：每格至少三个连字符，并可在两侧使用冒号；本文统一推荐固定形式 `|---:|---|---|---|`。

```markdown
| 序号 | 口播文案 | 重点词 | 素材搜索词 |
|---:|---|---|---|
```

> 本文中的代码围栏（例如 ` ```markdown ` 和结尾的 ` ``` `）只用于展示和方便复制。实际上传的 `.md` 文件不能包含代码围栏。

## 2. 字段规则

### 序号

- 必须从 `1` 开始，并按 `1、2、3……` 连续递增，不能跳号、重复或使用其他格式。

### 口播文案

- 不能为空。
- 建议每行表达一个完整、自然且长度适中的语义单元，便于生成口播和字幕。

### 重点词

- 可以为空。
- 同一行可以填写多个重点词，使用中文分号 `；` 或英文分号 `;` 分隔。
- 每个重点词去掉空白和标点后，必须确实存在于同一行的口播文案中；不要填写文案中没有出现的同义词、改写词或概括词。
- 为保证重点词动效能够生成，每个重点词去掉空白和标点后应至少包含 2 个可见字符。上传解析器目前可能接受单字重点词，但启用“重点词动效”后，生成阶段会因不足 2 个可见字符而失败，因此不要使用单字重点词。
- 重点词列定义需要触发的内容及其所在口播行，系统据此映射到对应的字幕时间位置；填写重点词本身不会自动开启动效。
- WebUI 中的“启用重点词动效”默认关闭。只有启用该开关后，重点词才会在成片中渲染；未启用时，文件中的重点词仍会被解析和校验，但不会显示动效。
- 启用“重点词动效”后，同一个重点词可以在不同文章行中重复出现，并按各自行对应的字幕时间位置分别触发动效。
- 同一单元格内的重复重点词会按首次出现的原顺序去重，并在 WebUI 预览中提示警告。

### 素材搜索词

- 可以为空，但第一行必须填写，以建立第一个场景。
- 同一行可以填写多个素材搜索词，使用中文分号 `；` 或英文分号 `;` 分隔。
- 每行最多填写 3 个素材搜索词。
- 每个搜索短语必须至少包含一个英文字母；不能使用只有数字的短语。
- 搜索短语可由英文字母、数字和空格组成。连字符 `-` 和撇号 `'` 只能出现在一个词的内部，且两侧都必须是字母或数字，例如 `well-being`、`bride's wedding`；`wedding-`、`-wedding`、`wedding'` 均非法。
- `&` 只能作为连接词使用，且两侧都必须有空格，例如 `love & marriage`；`R&D`、`love& marriage`、`love &marriage` 均非法。
- 合法示例：`wedding couple`、`2026 wedding`、`well-being`、`bride's wedding`、`love & marriage`。
- 非法示例：`123`（没有英文字母）、`R&D`（`&` 两侧没有空格）、`wedding-`（连字符不在词内部）、`婚礼 couple`（包含中文）。
- 搜索短语应具体描述希望检索到的画面，例如 `wedding couple`、`relationship communication`。
- 同一单元格内的重复搜索词会按首次出现的原顺序去重，并在 WebUI 预览中提示警告。

## 3. 场景划分逻辑

任何填写了素材搜索词的行都会开始一个新场景。该行之后搜索词为空的行会继承当前场景，直到下一行再次填写素材搜索词时，才开始下一个场景。

因此，不需要每一行都搜索素材。一个素材短片可以覆盖连续多句口播。第一行必须填写素材搜索词，才能建立第一个场景。

以下 4 行示例中，第 1 行和第 3 行填写了搜索词：

```markdown
| 序号 | 口播文案 | 重点词 | 素材搜索词 |
|---:|---|---|---|
| 1 | 清晨，城市开始苏醒。 | 清晨 | sunrise city |
| 2 | 人们带着期待走向新的一天。 | 期待 | |
| 3 | 夜幕降临，办公室依然亮着灯。 | 夜幕 | night office |
| 4 | 每一份坚持，都在靠近答案。 | 坚持 | |
```

- 第 1—2 行属于场景 1，共用 `sunrise city` 对应的画面。
- 第 3—4 行属于场景 2，共用 `night office` 对应的画面。

下面的内容与 `examples/markdown-scripts/marriage.md` 保持一致：

```markdown
# 婚姻，是一起把日子过成答案

| 3 | 真正长久的关系，离不开沟通，也少不了耐心。 | 沟通；耐心 | couple talking；relationship communication；patient partners |
| 4 | 当分歧出现时，先理解彼此，再寻找共同的方向。 | 理解；彼此；共同的方向 | |
| 5 | 岁月会改变容颜，却能让陪伴变得更加珍贵。 | 岁月；陪伴 | elderly couple；lifelong love |
```

## 5. 可直接复制给 AI 的完整转换提示词

复制以下提示词，并在末尾的“原始文章：”之后粘贴需要转换的文章：

```text
请将我粘贴在本提示词末尾的原始文章，整理成可直接保存并上传的 Markdown 口播稿。

转换要求：
1. 保留原始文章的核心观点和关键信息，但允许调整语序、删减重复表达，并整理为自然、流畅的口语。
2. 将内容拆成多行口播文案。每行只表达一个完整的语义单元，并适合在视频底部以单行字幕显示，避免句子过长。
3. 序号必须从 1 开始连续递增，不能跳号或重复。
4. 重点词只标记确实需要二次强调的内容。每个重点词必须逐字存在于同一行口播文案中，不能使用同义词或改写词；去掉空白和标点后必须至少包含 2 个可见字符，不要使用单字重点词。每行可以不填重点词，也可以填写多个；多个重点词使用中文分号“；”或英文分号“;”分隔。
5. 按连续几句话可以共用的画面含义划分场景，不要求每行都填写素材搜索词。任何新场景的第一行填写 1-3 个具体的英文素材搜索短语，该场景后续行的素材搜索词留空，直到下一个新场景开始。
6. 第一行必须填写素材搜索词，以建立第一个场景。
7. 每个素材搜索短语必须至少包含一个英文字母，可由英文字母、数字和空格组成。连字符“-”和撇号“'”只能出现在词内部，且两侧都必须是字母或数字，例如 well-being、bride's wedding；wedding- 非法。“&”只能作为两侧带空格的连接词，例如 love & marriage；R&D 非法。短语不能包含中文或其他符号。多个搜索短语使用中文分号“；”或英文分号“;”分隔，每行最多 3 个。
8. 严格只输出一个非空的 H1 一级标题和一个固定四列表格。标题格式为“# 标题”，表格必须紧随标题之后。
9. 固定表头必须原样输出。分隔行应使用四个有效的 Markdown 分隔单元格；为统一格式，推荐复制以下形式：
| 序号 | 口播文案 | 重点词 | 素材搜索词 |
|---:|---|---|---|
10. 不要添加解释、前言、结语、备注、列表、二级标题、代码围栏或任何表格外内容。
11. 表格至少包含一行口播数据；每一行都必须使用首尾竖线“|”，口播文案不能为空。
12. 如果单元格正文需要出现字面竖线“|”，必须输出为“\|”，否则会被解析成新列。例如，应写“选择 A \| B”，不能写“选择 A | B”。

输出前请自行检查：只有一个 H1、表头完全一致、序号连续、重点词逐字存在于同行文案、第一行搜索词非空、每行搜索词不超过 3 个，且场景切换位置合理。检查完成后只输出最终 Markdown 内容。

原始文章：
```

## 6. 上传前检查清单

- [ ] 文件中只有一个非空的 H1 一级标题。
- [ ] 一级标题后只有一个表格；固定四列表头必须完全一致；分隔行使用四个有效的 Markdown 分隔单元格，推荐复制本文展示的统一格式。
- [ ] 标题和表格之外没有正文、二级标题、列表、备注、代码围栏或其他内容。
- [ ] 表格至少包含一行口播数据，不是只有表头和分隔行的空表。
- [ ] 表格所有行均有首尾竖线，并且每行恰好包含四列。
- [ ] 单元格正文中的字面竖线均写成 `\|`，没有被误解析为新列。
- [ ] 序号从 1 开始连续递增，没有跳号或重复。
- [ ] 每行口播文案均不为空。
- [ ] 每个重点词去掉空白和标点后，都确实存在于同行口播文案中。

- [ ] 每个素材搜索短语至少包含一个英文字母，`&` 两侧有空格，连字符和撇号只出现在词内部，且每行最多 3 个。
- [ ] 第一行素材搜索词不为空。

## 7. 常见错误表

| 常见错误 | 原因 | 修复方式 |
|---|---|---|
| 扩展名或编码错误 | 文件不是 `.md`，或使用了非 UTF-8 编码，解析器无法按上传格式读取。 | 将文件扩展名改为 `.md`，并以 UTF-8 或带 BOM 的 UTF-8 重新保存。 |
| 标题、表格之外有额外内容 | 加入了前言、说明、二级标题、列表、备注、代码围栏，或在表格结束后继续写正文。 | 删除所有额外内容，只保留一个 H1 和一个四列表格。 |
| 表头错误或分隔行无效 | 修改了固定列名、列顺序或列数，或者分隔行没有恰好包含四个有效分隔单元格。有效分隔单元格至少有三个连字符，并可在两侧使用冒号。 | 恢复固定表头；为统一格式，建议原样使用本文第 1 节展示的分隔行。 |
| 单元格中的竖线未转义 | 正文中的字面竖线（<code>&#124;</code>）被解析器当成列分隔符，导致该行不再是四列。 | 在字面竖线前添加反斜杠，例如把 <code>选择 A &#124; B</code> 改为 <code>选择 A &#92;&#124; B</code>。 |
| 序号跳号 | 序号没有从 1 开始连续递增，或出现重复、非数字内容。 | 按表格行顺序重新编号为 1、2、3……。 |
| 重点词不在同行 | 重点词使用了同义词、改写词，或去掉空白和标点后仍未出现在同一行口播文案中。 | 将重点词改为同行文案中确实出现的原词，或删除该重点词。 |
| 单字重点词 | 上传解析器目前可能接受单字重点词，但启用重点词动效后，生成阶段要求重点词去掉空白和标点后至少包含 2 个可见字符，否则会失败。 | 从同行文案中选择至少两字的词组作为重点词，或删除该重点词。 |
| 使用中文素材搜索词 | 素材搜索短语不是英文，无法通过格式校验。 | 改为具体的英文搜索短语，例如将“婚礼夫妻”改为 `wedding couple`。 |
| 素材搜索词符号位置非法 | `&` 两侧没有空格，或连字符、撇号出现在词首或词尾，例如 `R&D`、`wedding-`。 | 改为符合语法的英文短语，例如 `love & marriage`、`well-being`、`bride's wedding`。 |
| 一行超过 3 个搜索词 | 同一单元格用分号分隔后得到 4 个或更多素材搜索词。 | 只保留最具体、最相关的 1-3 个英文搜索短语。 |
| 第一行搜索词为空 | 第一个场景没有起始搜索词，系统无法建立场景。 | 在第一行填写 1-3 个具体的英文素材搜索短语。 |
