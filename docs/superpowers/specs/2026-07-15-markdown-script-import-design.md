# Markdown 口播任务导入设计

## 背景

用户会在外部让 AI 生成完整口播稿 Markdown 文件。MoneyPrinterTurbo 只负责解析和执行，不再调用大语言模型补写文案、重点词或素材搜索词。上传后先展示结构化预览，校验通过后由用户点击生成视频。

本功能复用现有本地 TTS、字幕、横竖版、素材平台、重点词字体、动画、颜色、固定音效和背景音乐设置。Markdown 只描述内容，不保存生成参数。

## 目标

- 一份 Markdown 同时描述视频标题、分行口播文案、行级重点词和场景级素材搜索词。
- 同一个重点词可在不同文案行分别触发，不再受全稿首次匹配限制。
- 一个素材场景可覆盖多行口播；空搜索词行延续上一场景。
- 每个场景支持按顺序尝试多个英文备用搜索词。
- Markdown 模式不调用大语言模型，缺失内容必须明确报错。
- WebUI 在开始耗时生成前提供可核对的解析预览。

## 非目标

- Markdown 不保存音色、横竖版、字体、字幕、动画、音效、素材平台、分辨率或背景音乐设置。
- 第一版不支持任意 Markdown 布局、自然语言标签或内嵌 JSON。
- 第一版不让程序自动推断场景边界、重点词或素材搜索词。
- 本功能不移除现有手动输入文案和 AI 生成文案的工作流。

## 文件格式

文件使用 UTF-8 编码和 `.md` 扩展名，只包含一个一级标题和一张任务表格。

```md
# 婚姻二字

| 序号 | 口播文案 | 重点词 | 素材搜索词 |
|---:|---|---|---|
| 1 | 婚姻二字写起来只有两笔。 | 婚姻二字；只有两笔 | wedding couple；married couple |
| 2 | 走进去却是一生的功课。 | 一生的功课 | |
| 3 | 它不是找一个完美的人。 | 完美的人 | couple talking；married couple |
| 4 | 而是遇见一个愿意一起面对生活的人。 | 面对生活 | |
| 5 | 平凡日子里也别忘了好好说话。 | 平凡日子；好好说话 | couple holding hands |
```

### 标题与列

- `# 一级标题`是视频标题，并写入现有视频主题字段。
- 表格列名和顺序固定为 `序号`、`口播文案`、`重点词`、`素材搜索词`。
- 表格物理顺序就是口播和场景顺序。
- 序号必须从 1 开始连续递增，不负责重新排序。
- 口播文案不能为空。文案中的 `|` 必须写成 `\|`。

### 重点词

- 重点词允许为空；多个重点词使用 `；` 或 `;` 分隔。
- 每个重点词必须出现在本行口播文案中。匹配时忽略空白和常见标点，与现有可见文字归一化规则一致。
- 同一个词在多行中被标记时，每一行分别生成重点词提示。
- 同一行多个重点词沿用现有多词同屏、分层、左中右位置、随机动画和固定音效规则。

### 素材搜索词与场景

- 素材搜索词必须是英文短语。一个场景允许 1 至 3 个备用搜索词，使用 `；` 或 `;` 分隔。
- 第一行必须填写素材搜索词。
- 某行搜索词非空表示新场景从该行开始。
- 某行搜索词为空表示该行延续最近一个场景。
- 场景持续到下一个非空搜索词行开始之前，最后一个场景持续到口播结束。
- 备用词按文档顺序尝试，不通过大语言模型翻译或改写。

## 结构化模型

解析层产生与 WebUI 和任务编排解耦的结构：

```text
ImportedScriptDocument
├─ title
├─ rows[]
│  ├─ number
│  ├─ text
│  ├─ emphasis_terms[]
│  └─ material_search_terms[]
└─ scenes[]
   ├─ first_row
   ├─ last_row
   └─ material_search_terms[]
```

解析结果随任务参数和历史记录保存。为兼容现有管线，同时派生：

- `video_subject`：一级标题。
- `video_script`：按表格物理顺序用换行连接全部口播文案。
- 结构化行与场景数据：用于行级重点词和场景级素材时间线，不能只压平到现有全局 `emphasis_terms` 或 `video_terms`。

普通手动文案和旧任务没有结构化字段时继续走现有逻辑。

## WebUI 流程

1. 在文案区域增加 `.md` 文件上传入口。
2. 文件上传后立即解析，不自动启动视频任务。
3. 成功预览展示：
   - 视频标题、口播行数和场景数；
   - 合并后的完整口播稿；
   - 每个场景覆盖的行号和备用素材搜索词；
   - 每行口播文案和重点词。
4. 错误按行号和字段展示；存在阻断错误时禁用生成按钮。
5. 校验通过后，用户点击现有生成按钮。WebUI 当前选择的音色、比例、样式和素材平台继续生效。
6. 恢复历史任务时恢复解析结果和预览；浏览器不尝试恢复原始上传控件。

## 生成数据流

1. 使用结构化文案直接建立 `video_script`，跳过文案生成。
2. 使用当前 WebUI 设置的本地 TTS 生成音频，再生成或对齐字幕。
3. 将每行规范化文本映射到完整文案和字幕时间轴，得到行级开始与结束时间。
4. 重点词以“源行号 + 行内字符位置”映射到该行时间范围。相同文本出现在多行时不会抢占前一次匹配。
5. 将场景首尾行时间合并为场景时间范围。
6. 对每个场景按顺序尝试英文备用搜索词，并保留现有横竖比例和分辨率过滤。
7. 一个场景可以用一个素材片段覆盖多行；单个素材不足以覆盖场景时，继续从该场景搜索结果补充片段。素材在场景末尾裁切，不跨入下一场景。
8. 按场景时间线拼接素材，再叠加主字幕、行级重点词、提示音和其他现有音轨。

Markdown 模式不得调用 `generate_script()`、`generate_terms()` 或 `generate_emphasis_terms()` 的大语言模型分支。格式缺失、对齐失败或素材耗尽均直接返回可诊断错误。

## 校验与错误处理

以下错误阻止生成：

- 文件扩展名不是 `.md` 或内容不是 UTF-8。
- 缺少一级标题、固定四列表格或任一必填列。
- 存在多余列、无法解析的单元格或未转义的 `|`。
- 序号不是从 1 开始连续递增的正整数。
- 口播文案为空。
- 第一行素材搜索词为空。
- 重点词无法在对应行文案中匹配。
- 素材搜索词包含中文、某场景没有可用词或备用词超过 3 个。

以下情况自动处理并在预览中提示：

- 中文和英文分号都作为列表分隔符。
- 清理字段首尾空白。
- 重点词和搜索词按原顺序去重。
- 空重点词行正常生成，但没有重点词效果。
- 空搜索词行继承上一场景。

生成阶段错误必须包含场景或行号、相关文案和尝试过的搜索词。例如：

```text
场景 3 素材搜索失败：couple talking；married couple
对应文案：第 5～7 行
```

字幕对齐失败必须指出无法映射的行和重点词，不能静默丢弃。

## 兼容性与安全

- 现有文本框输入、现有 AI 生成按钮和旧任务格式继续可用。
- 上传文件只作为文本读取，不执行其中的 HTML、脚本、链接或代码块。
- 解析器不接受路径、远程 URL 或 Markdown 内嵌资源作为素材输入。
- 任务记录保存规范化后的结构数据，日志不记录素材平台密钥。

## 测试与验收

### 解析测试

- 正常四列表格、转义竖线、两种分号和空重点词。
- 序号、列名、UTF-8、必填字段及英文搜索词校验。
- 空搜索词继承上一场景，多备用词保持顺序并去重。

### 时间轴测试

- 同一重点词在不同文案行分别生成提示。
- 同一行多个重点词按文本位置进入并保持现有分层规则。
- 一个场景覆盖多行，场景边界与行时间范围一致。
- 素材不足时尝试后续备用词，且素材不跨场景。

### 流程测试

- WebUI 上传后显示预览，错误时禁用生成。
- Markdown 模式对大语言模型函数设置失败桩，仍能完成到素材搜索阶段。
- 任务历史保存并恢复结构化文档。
- 普通文案和旧任务继续通过现有测试。

### 真实样片

使用婚姻主题 Markdown 生成横版样片，验证：

- 一个素材场景覆盖多行口播；
- 场景按 Markdown 边界切换；
- 重复重点词按行分别出现；
- 同行多重点词、主字幕、动画和提示音正常；
- 全流程不调用大语言模型。
