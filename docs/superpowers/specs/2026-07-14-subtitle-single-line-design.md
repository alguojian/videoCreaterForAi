# 本地字幕单行显示设计

## 背景

当前本地 CosyVoice3 + Qwen ForcedAligner 流程会把字幕按 `subtitle_max_chars = 20` 硬切。婚姻测试文本因此生成了“的功课。”这样的短尾字幕。视频渲染层还会根据文字宽度自动换行，导致用户无法稳定获得单行字幕。

## 目标

- 字幕显示层默认不显示中文/英文逗号和句号。
- 单条字幕优先保持单行，默认上限调整为约 14 个中文字。
- 默认视觉样式为底部居中、白色文字、透明背景，并使用轻微黑色描边增强对比度。
- 字幕位置在同一输出视频内保持固定，不随每条文字长度改变垂直位置。
- 优先在逗号、句号等语义边界切分，而不是直接在固定字符数处切断。
- 如果语义边界产生很短的尾部，且合并后仍不超过单行上限，则并回前一条。
- TTS 的 `spoken_text` 和标点停顿不改变，Qwen 对齐仍以真实音频为准。
- 对齐失败、无字幕或其他字幕提供方的既有回退行为保持不变。

## 方案

采用“语义边界优先 + 单行长度限制”的字幕构建策略：

1. TTS 继续使用包含标点的原始朗读文本，保证 CosyVoice 的停顿自然。
2. 字幕构建器使用显示文本和 Qwen 字符时间轴，识别逗号、句号等边界；边界字符参与时间范围计算，但不写入 SRT 文本。
3. 将相邻的短语片段打包到约 14 个可见字符以内，优先形成完整短语；超过上限时才按字符上限拆分。
4. 最终 SRT 的每条文本都不含逗号/句号，并通过测试保证不超过默认单行上限。
5. 视频渲染仍保留宽度安全保护；在默认 1080×1920、60 号字体和现有字幕边距下，14 个中文字作为单行目标。
6. 测试视频使用白字、黑色 2px 描边、无背景色和 `bottom` 位置，贴合参考效果；用户仍可通过历史参数显式启用字幕背景。

示例：

```text
输入：婚姻二字，写起来只有两笔，走进去却是一生的功课。

输出：婚姻二字写起来只有两笔
      走进去却是一生的功课
```

## 配置

- `config.example.toml` 的 `local_voice.subtitle_max_chars` 默认值改为 `14`。
- 用户当前 Windows `config.toml` 同步使用 `14`，使 WebUI 立即使用新规则。
- `subtitle_max_lines` 同步设为 `1` 作为配置意图记录；单行实际由字幕字符上限和视频渲染宽度共同保证。
- 不新增云端字幕配置，不改变原有 Edge/Whisper 行为。

## 测试与验收

- 新增字幕构建回归测试：示例文本不输出逗号/句号、不产生 3 字短尾、每条不超过 14 个可见字符。
- 保留现有 Qwen 对齐时间、零时长修复和 SRT 写入测试。
- 运行本地字幕相关测试和项目全量测试（排除 `third_party/`）。
- 重新生成婚姻主题视频，检查 SRT 和最终画面：字幕单行、无逗号句号、没有“的功课。”孤立短尾。
