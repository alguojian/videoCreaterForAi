# 横版重点词动效与固定音效库设计

## 目标

生成默认 16:9 横版视频，在原有底部白色主字幕之外，叠加与旁白时间匹配的重点词动画。每个重点词从固定精选的本地音效库中随机选择一个短提示音；颜色、动效和音效对不同任务有变化，但同一任务重渲染时结果保持一致。

## 范围

- 将 WebUI 与 `VideoParams` 的默认视频比例设置为 `16:9`；保留现有比例枚举供旧任务和 API 显式指定。
- 主字幕维持现有底部、白色、黑描边、透明背景、单行规则。
- 新增重点词图层，显示在横版画面中部安全区，不遮挡底部主字幕。
- 自动提取重点短语；用户可在 WebUI 输入逗号分隔的短语，手动覆盖自动结果。
- 每个重点词都叠加短音效，不调用任何生成模型。

不在本次范围内：复制剪映的专有音效素材、网页预览对比页、逐帧人工排版工具、改变 TTS 或字幕对齐流程。

## 数据流

1. 任务得到文案、音频和 SRT 后，重点词服务从文案与 SRT 生成 `EmphasisCue` 列表。
2. 用户填写的手动重点词优先；未填写时，服务调用现有 LLM 文本接口输出严格 JSON 短语列表。LLM 不可用或输出无效时，回退为按句子和 SRT 文本提取的确定性规则，视频不会失败。
3. 每个重点词必须能在某一 SRT cue 中精确匹配。开始/结束时间由该 cue 的字符比例换算；匹配不到的词记录警告并跳过。
4. 基于 `task_id + cue 序号` 创建伪随机种子，从预设配色、动效与本地音效池中稳定选取样式。
5. `generate_video()` 在主字幕上方合成重点词动画，并把同一时间轴上的提示音混入旁白和 BGM。
6. 将最终 `EmphasisCue`（词、时间、颜色、动效、音效文件）写入任务目录的 `emphasis.json`，便于排查和复现。

## 重点词规则

- 单个短语为 2～8 个可见中文字符或 2～4 个英文单词。
- 自动模式每段主字幕最多一个重点词，避免画面过密；手动模式按用户给出的匹配结果显示。
- 重点词可在同一条主字幕内按语音位置出现，默认展示 0.75～1.35 秒，最短 0.45 秒，并限制在视频时长内。
- 对同一时刻重叠的重点词，按时间轴顺序错开 0.12 秒，仍保证每个词都有自己的动画和音效。

## 视觉样式

重点词使用粗体中文字体、黑色 3px 描边、透明背景，默认位于横版画面纵向 47% 的安全区。颜色和动效从以下固定集合稳定随机选择：

- 配色：橙黄、红橙、蓝紫、青绿、粉紫、亮黄。
- 动效：弹出回弹、左滑入、右滑入、快速缩放强调、轻微震动、盖章落入。
- 位置：以画面中部为主，左右安全区交替；不会进入底部主字幕区域。

随机只改变已验证的组合，不生成新的颜色、文字样式或音效，因此视觉质量稳定。

## 音效

- 提供约 12 个本地短音效，分为 `pop`、`whoosh`、`hit`、`sparkle` 四组。
- 每个素材必须可在本地离线播放、时长不超过 0.6 秒，并具有明确可商用授权记录；不使用剪映或其他专有平台的音效文件。
- 动效优先匹配同类音效：滑入使用 `whoosh`，回弹/震动使用 `pop`，缩放/盖章使用 `hit`，柔和提示使用 `sparkle`。
- 音效默认音量为旁白的低级别补充；若与 BGM 同时存在，保持旁白优先，限制混音峰值避免爆音。

## WebUI A

新增独立的“重点词动效”设置：

- 启用重点词动效；
- 手动重点词（可选，逗号分隔）；
- 随机配色；
- 随机动效；
- 启用重点词音效；
- 音效音量。

所有设置进入 `VideoParams`，因此 API、任务队列和脚本生成均使用同一参数。默认启用横版 16:9；重点词效果默认关闭，避免改变历史任务，用户开启后使用本设计。

## 测试与验收

- 单元测试：手动词优先、LLM JSON 解析失败回退、SRT 匹配与时间计算、稳定随机样式、无效/越界词跳过。
- 渲染测试：为不同动效创建可检查的 MoviePy clips，验证安全位置、时长和叠加顺序。
- 音频测试：每个重点词生成一个有效音效 clip，混音不移除旁白和 BGM。
- 集成验收：使用“婚姻”文案生成 1920×1080 横版视频，确认横版素材、底部主字幕、多个不同颜色/动效的重点词，以及每个重点词的提示音。
- 全量回归：运行 `pytest -q --ignore=third_party`。
